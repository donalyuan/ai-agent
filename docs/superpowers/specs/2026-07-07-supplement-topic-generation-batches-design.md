# 补充选题生成批次设计

## 背景

内容策略页已经支持选题 Agent 批量生成候选、按历史批次查看选题，以及在历史生成页管理批次内选题。当前每次选题 Agent 消息都会创建一条 `topic_generation_batches`，生成出的 `content_topics.batch_id` 指向该新批次。

用户确认的新需求是：已经生成过选题的历史批次需要能够再次补充选题，并且补充结果应作为“原批次的补充批次”存在。

## 设计结论

补充生成不把新选题追加回原批次。系统创建新的 `topic_generation_batches` 记录，并通过 `supplement_of_batch_id` 指向原始批次。新生成的 `content_topics.batch_id` 指向补充批次本身。

这样保留“一次生成记录对应一次真实生成事件”的审计语义，同时能在历史生成页把原批次和补充批次组织到同一个上下文下查看。

## DDD

`TopicGenerationBatch` 继续表示一次选题生成事件。新增自关联字段 `supplement_of_batch_id` 表示当前批次补充自某个原始批次。

领域规则：

- 原始批次和补充批次必须属于同一项目。
- 只允许补充成功且仍有可见选题的批次。
- 补充批次可以继续被补充；展示时归入同一个原始批次上下文。
- 原始批次不可因补充动作改写 `requested_count`、`prompt`、`source_run_id` 或原有选题关联。

## BDD

操作者进入“历史生成”，选择一个历史批次，点击“补充选题”，输入补充要求和数量。系统调用选题 Agent 生成新候选，创建补充批次，并把新选题关联到该补充批次。

历史生成页展示原始批次详情时，应能看到它的补充批次列表。操作者可以切换查看原始批次或任一补充批次的选题。

## SDD

后端新增字段：

- `topic_generation_batches.supplement_of_batch_id UUID NULL REFERENCES topic_generation_batches(id) ON DELETE SET NULL`

后端接口和响应扩展：

- 选题 Agent 消息入口支持携带 `supplement_of_batch_id`。
- 批次列表返回补充关系字段。
- 批次详情或列表响应应能让前端区分原始批次和补充批次。

前端扩展：

- 历史生成页在批次详情中提供“补充选题”入口。
- 补充表单复用现有选题 Agent 输入规则。
- 左侧历史列表按原始主题组展示，补充批次只在右侧关联补充批次区域展示。
- 当前主题选题区聚合展示原始批次和补充批次选题，并通过来源标签区分。

非目标：

- 不把补充选题直接写回原始批次。
- 不修改旧 migration，新增递增 migration。
- 不实现失败批次审计页。
- 不实现移动端适配。

## TDD

后端测试覆盖：

- 补充生成创建新批次，原批次不被改写。
- 补充批次的 `supplement_of_batch_id` 指向原批次。
- 补充批次和原批次必须属于同一项目。
- 不允许补充不存在、失败、空批次。
- 批次列表和选题查询仍排除软删除选题。

前端测试覆盖：

- 历史生成页展示补充入口。
- 成功补充后刷新批次列表，保持选中原始主题组。
- 关联补充批次只作为来源和审计记录展示，不作为左侧独立主题入口。
