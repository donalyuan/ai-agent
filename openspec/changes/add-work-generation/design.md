# 作品生成 Design

## Context

用户要求的“一次生成”是产品事务：一次汇总全片素材、一次确认、一次创建作品运行，而不是逐图片提交。Seedance 单任务受到参考图、时长和提示词限制，因此长作品必须由后台拆分为连续子任务并在本地合成，不能把一次用户操作描述成永远只有一个上游请求。

## Goals / Non-Goals

**Goals:**

- 从完整主画面清单生成可见、可编辑、可确认的作品计划。
- 按模型真实能力校验时长、比例、分辨率、原声和分段。
- 将 Seedance、TTS/ASR、已有音频、字幕和 FFmpeg 组织为一个作品级运行。
- 锁定运行输入快照，防止执行中修改污染当前版本。

**Non-Goals:**

- 不负责生成任务列表、人工重试 UI 和作品库生命周期。
- 不实现未选定接口的 AI 音乐与音效。
- 不宣称 Seedance 原声可分离人声、BGM 和音效。

## DDD

`Work` 表示作品身份，`WorkVersion` 表示不可变生产快照，`WorkPlan` 表示尚未执行且可迭代的 Agent 计划，`WorkGenerationRun` 表示一次用户确认创建的运行。

`WorkPlan` 输入包括 `SceneVisualManifest`、脚本/旁白、模型选择、时长策略、画面规格、声音模式、字幕配置和已有音频。输出包括全片意图、最终提示词、合法视频分段、每段提示词、时间轴、条件步骤和非金额资源用量。

计划可被 Agent 对话修改并产生新版本；任何输入或模型能力变化都会使旧计划失效。运行创建后锁定计划、模型、素材、参数、音色和能力版本快照。运行中对话修改进入后续草稿，不改变当前运行。

## BDD

操作者进入作品生成后看到完整镜头清单和作品 Agent 对话。Agent 读取全部图片与镜头描述，生成信息充分的全片方案和分段提示词；用户可以对话或直接编辑，确认前不会调用视频模型。

操作者选择总时长、比例、分辨率以及声音模式。系统实时按所选模型能力重算分段和用量。确认弹窗展示 LLM、视频、TTS/ASR 模型、视频任务数、总秒数、字符数和产物；一次确认创建一个运行。

Seedance 子任务完成后，FFmpeg 拼接视频并根据声音模式加入 TTS、原声和已有音频，处理字幕后输出标准 MP4 与 SRT。

## SDD

### 模型与能力

方案 LLM、视频、TTS 按类型独立选择，可预选 Admin 默认模型。视频能力目录至少描述时长、比例、分辨率、参考图上限、提示词约束和 `generate_audio`。TTS 能力来自声音 change 的版本化目录。Agent 推荐必须属于当前可用目录。

模型停用/删除时保留草稿原选择并阻止提交，不静默替换。运行快照保存模型 ID、供应商、上游模型、能力版本和参数，不保存密钥。

### 分段算法

作品总时长允许 `15/30/45/60秒`、`4~60秒` 自定义或跟随配音。固定时长表示最终成片目标；跟随配音在 TTS 成功后以实际音频时长重新规划，超过 60 秒必须阻止。

Seedance 分段优先落在分镜边界，每段必须符合当前能力。首版确认边界为 `4~15秒`、参考图不超过 9 张；尾段不足 4 秒时重分配相邻段。中文分段提示词按官方建议控制在 500 字以内，但不能静默删除核心角色、场景、动作与连续性约束。

### 声音模式

| 模式 | Seedance | TTS | 字幕来源 |
| --- | --- | --- | --- |
| 独立 TTS | `generate_audio=false` | 生成 | TTS 时间戳 |
| Seedance 原声 | `generate_audio=true` | 不生成 | ASR 原声 |
| Seedance 原声 + TTS | `generate_audio=true` | 生成 | TTS 为主，原声作背景 |

混合模式由 FFmpeg 在 TTS 区间压低不可分轨原声。页面必须提示双重人声风险；Agent 可要求 Seedance 无对白，但不得保证。视频模型不支持原声时只提供独立 TTS。

已有 BGM、环境音和动作音效只作为素材引用进入多轨时间轴，设置起止、音量和淡入淡出，不创建 AI 生成任务。

### 合成

FFmpeg 负责视频拼接、音轨放置、ducking、响度/时长处理、字幕烧录和封装。标准输出为 `MP4(H.264) + AAC`。默认烧录字幕并独立保存 SRT；关闭烧录时输出无烧录成片和外挂 SRT。输入缺失或媒体校验失败不得生成伪成功成片。

### 确认协议

确认必须携带规划版本和 `Idempotency-Key`。相同 key 返回原运行；计划过期、主图变化或能力版本变化时拒绝执行。确认展示任务数、视频秒数、TTS 字符数、ASR 时长和输出物，不维护价格或金额。

## TDD

- 领域：计划版本、输入失效、运行快照、模型停用和一次提交幂等。
- 分段：4/15/60 秒边界、尾段重分配、9 图上限、中文提示词、无法合法分段。
- Provider contract：Seedance 创建/查询、原声能力、脱敏和 fake responses。
- 音频：三种声音模式、已有音频时间范围、混合 ducking 和双人声提示。
- FFmpeg：编码、时长、轨道、字幕烧录/外挂和输入失败。
- 前端/E2E：可见 Agent 对话、提示词编辑、动态选项、再次确认、无金额字段。

## Decisions

### 一次用户提交，后台多子任务

既满足完整作品的一次操作体验，也遵守上游限制。逐图提交会破坏一致性；强行单个上游请求无法覆盖长作品。

### 作品计划与运行分离

计划允许对话迭代，运行则锁定不可变快照；两者分离可以可靠判断旧计划失效并防止执行中污染。

### FFmpeg 确定性后处理

视频模型负责生成视觉片段，FFmpeg 负责可测试的拼接、混音、字幕和封装。对不可分轨原声只做整体 ducking，不承诺源分离。

## Risks / Trade-offs

- [跨片段连续性波动] -> 优先分镜边界、统一全片约束、相邻段上下文和后续节点级重生。
- [跟随配音超过 60 秒] -> 明确阻止并要求缩短旁白，不静默截断。
- [混合模式双重人声] -> 默认独立 TTS，混合前显著警告。
- [能力目录过期] -> 确认时重新校验版本，失效计划必须重建。
- [一次提交被误解为一次 API] -> UI 展示一个作品运行及实际子任务数量。

## Migration Plan

1. 先以 fake provider 建立领域、分段、确认和 FFmpeg 契约。
2. 对接主画面 manifest、声音能力和素材登记。
3. 原型明确确认后实现作品生成工作区。
4. 真实 Seedance/TTS/ASR 验证必须单独获许可并限制 60 秒、并发、任务数和重试。
5. 回滚时停用新菜单和 Worker 消费，保留作品草稿、运行和已生成素材。

## Open Questions

无阻塞问题。真实 provider 字段在实施前仍须按届时官方文档和受控 contract 验证。
