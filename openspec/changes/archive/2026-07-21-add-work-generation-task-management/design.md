# 作品生成任务管理 Design

## Context

作品级运行是多步骤 DAG。外部异步视频任务可能在本地 Worker 重启后仍继续运行，如果没有稳定上游任务身份和恢复协议，简单重试会产生重复调用。另一方面，某个分段失败不应导致成功分段、TTS 和素材全部重做。

## Goals / Non-Goals

**Goals:**

- 提供作品运行和子任务的真实、可解释进度。
- 确保上游任务可恢复、确认请求幂等、失败节点可独立重试。
- 保留永久审计，同时允许清理默认工作视图。

**Non-Goals:**

- 不接管作品规划和版本内容。
- 不替代平台级队列与跨 Agent 工作流监控。
- 不用前端状态作为并发或防重复调用的唯一保障。

## DDD

`WorkGenerationRun` 是一次作品确认的运行聚合根；`WorkGenerationStep` 是 `plan/tts/video_segment/asr/subtitle/mix/compose` 等逻辑节点；`ProviderTaskAttempt` 是节点的一次具体执行。

Step 状态为 `pending -> running -> succeeded | failed | cancelled`。失败重试不覆盖原 attempt，而是创建新 attempt。Run 的阶段和进度由锁定 DAG 中必需步骤与 attempt 终态确定性聚合，前端不自行估算。

页面三个主视图是服务端状态的展示分组，不是新的领域状态：`未生成` 对应尚未开始外部调用的排队运行，`生成中` 对应存在运行中或待执行必要步骤的运行，`已完成` 只对应成功产出完整结果的运行。`failed / waiting_manual` 进入独立“需处理”入口，`cancelled` 与已隐藏运行通过更多筛选访问，禁止把异常或取消状态归入“已完成”。

上游身份分为业务幂等键、供应商请求追踪 ID 和上游任务 ID。取得上游任务 ID 后，任何 Worker 只能恢复查询原任务；不得创建新 attempt 冒充查询重试。

## BDD

任务页列表密集展示作品、版本、当前阶段、成功/失败子任务数和用量。选择一行后，右侧按实际执行顺序展示步骤；不适用于当前声音模式的步骤显示未规划，不显示失败。

操作者确认生成作品后，作品生成页显示“查看生成任务”按钮；点击后进入生成任务页并定位本次运行。任务页顶部使用“未生成 / 生成中 / 已完成”三段筛选，异常运行从独立“需处理”入口进入。

生成任务页复用作品生成页的全局工作台骨架。页面切换时顶部栏、品牌区、完整左侧业务菜单、导航宽度和内容起点保持不变，只替换作品生产内容区和二级菜单高亮。

若一个 Seedance 分段失败，操作者看到该分段、再次调用秒数和受影响的合成节点。确认后只重试该分段，成功片段继续复用。若响应丢失且无法判断上游是否已创建任务，系统停止自动重提并要求人工判断。

## SDD

### 运行与 attempt

每个 attempt 至少保存 step ID、attempt 序号、模型/工具快照、输入摘要、状态、租约、开始/结束时间、资源用量、错误分类/摘要、请求追踪 ID、上游任务 ID 和结果素材引用。凭据不得保存。

运行状态、当前阶段和进度由数据库聚合函数在 step/attempt 状态变化后统一刷新；必需节点失败时，依赖它的必要下游递归转为阻塞并记录依赖原因。这样 API 列表、详情和 Worker 观察到的是同一状态事实。

相同人工操作的 `Idempotency-Key` 必须永久映射到同一 attempt。数据库约束保证同一失败节点最多一个在途重试；Worker 领取使用租约和条件更新。

### 恢复与重试

- 未获得上游任务 ID 且错误明确为临时错误：同模型自动重试最多 1 次。
- 已获得上游任务 ID：只查询、恢复或按能力取消原任务。
- 响应丢失且无法证明未提交：转人工处理，禁止自动重提。
- 人工重试：只针对失败节点，新建 attempt，执行必要下游本地步骤。
- 跨模型重试：属于新计划或新版本，不计为原节点自动重试。

### 取消与隐藏

排队且未调用外部服务的步骤可本地取消。运行中任务仅在供应商支持时发送取消，并保存供应商最终状态；不支持取消时不得伪造 cancelled。

provider 是否支持运行中取消锁定在具体 attempt；取消请求时间和脱敏响应随 attempt 永久审计。API 只把具备上游任务 ID 且全部在途 attempt 均声明支持取消的运行转为 `cancelling`，Worker 随后向原上游任务转发一次取消并继续查询其最终状态。

作品生成后台调度使用独立 `WORK_GENERATION_WORKER_ENABLED` 开关和轮询间隔，不复用 provider 能力开关。`WORK_GENERATION_FAKE_PROVIDER_ENABLED` 只允许无外部费用的 fake provider 执行；健康接口必须反映后台循环是否实际启用。

隐藏采用 `dismissed_at` 一类本地可见性事实，不修改失败终态，不删除 run、step、attempt、错误、用量和素材，也不调用 Worker/供应商。

### 页面入口与状态筛选

确认 API 成功返回 `run_id` 后，前端以该稳定身份构造生成任务直达入口，不使用作品标题或列表位置猜测目标运行。生成任务页的三个主状态筛选由服务端返回的展示分组驱动；阶段、作品、时间、已取消和已隐藏任务通过更多筛选访问。失败与状态不确定运行始终保留独立“需处理”入口。

直达页面时前端只用 `run_id` 调用详情 API 一次，依据任务真实状态确定所属视图，再请求该视图列表。URL 中保留选中任务身份不得导致轮询持续请求 `view=all`，否则标签高亮与列表状态会失配。

列表 API 同时返回当前筛选任务和项目级状态计数。顶部总数、三个主状态、“需处理”和“已取消”数量全部消费服务端计数，不得用当前页面 `tasks.length` 推算；`cancelled` 是更多筛选中的正式服务端视图，`include_hidden` 只控制已隐藏审计记录，不再与取消状态混用。

普通菜单入口加载列表后保持未选择状态，避免第一条任务在没有用户动作时已经显示详情，导致“查看”没有可观察反馈。点击“查看”后先展示详情加载状态，再以请求对应的 `run_id` 更新选中行和右侧详情；快速连续选择时只允许最后一次选择的响应更新界面。携带 `run_id` 的作品生成直达入口仍按既有规则自动定位。

### 统一工作台骨架

Video Agent 全局工作台骨架以作品生成页当前 `WorkspaceShell` 为基准。生成任务页不得使用二级菜单条件触发独立顶部栏、品牌区或左侧导航布局；页面专属 CSS 只能控制任务标题、列表、详情和内部滚动区域。后续作品生产页面继续继承同一骨架。

### 桌面字号层级

生成任务页与作品生成页使用同一可读字号基线：辅助信息最低 `12px`，任务名、进度、筛选控件、状态和步骤名称使用 `13~14px`，列表与详情区块标题不低于 `16px`。高密度列表通过列宽和行高保持扫描效率，不得以 `9~11px` 字号换取密度；固定工作台宽度下必须继续避免文本裁切和横向溢出。

## TDD

- 状态聚合：并行分段、条件步骤、必需节点失败、取消和成功终态。
- 幂等/并发：相同 key、不同页面并发、租约恢复、单节点最多一个在途 attempt。
- Provider：取得任务 ID 后恢复、提交前临时错误一次、响应不确定转人工。
- 重试：单分段、TTS、合成失败，验证成功素材和模型任务不重复。
- 取消/隐藏：支持与不支持取消、重复隐藏、审计保留。
- 前端/E2E：高密度列表、右侧详情、筛选、重试确认和无金额字段。
- 前端/E2E：普通入口不自动标记第一条为已查看；点击“查看”立即反馈并打开对应详情，连续点击不会被过期响应覆盖。
- 前端/E2E：确认成功后出现直达按钮，点击定位当前 `run_id`；三态主筛选与“需处理”异常入口互不混淆。
- 前端/E2E：作品生成与生成任务的顶部栏、品牌区、左侧导航和内容起点坐标一致，切页时不得发生骨架跳变。
- 前端/E2E：生成任务可见文字字号符合 `12/13~14/16px` 层级，表格、步骤详情和页面边界无文本裁切或横向溢出。

## Decisions

### Step 与 Attempt 分离

Step 表达业务节点，Attempt 表达每次实际执行。这样可保留失败历史、支持节点重试，并准确回答是否再次调用了供应商。

### 服务端确定性聚合

进度基于锁定 DAG 和数据库状态计算，避免不同客户端对百分比和终态判断不一致。

### 不确定提交转人工

无法证明上游未创建任务时，自动重提的重复调用风险高于等待人工处理，必须停止。

### 作品生成页作为工作台骨架基准

作品生成页已经使用 Video Agent 的共享 `WorkspaceShell`。生成任务只新增业务内容，不建立独立全局 Shell，避免同一一级模块在二级页面切换时出现页头和导航跳变。

## Risks / Trade-offs

- [上游缺少幂等或查询能力] -> 保存请求追踪，状态不确定时转人工，不盲重提。
- [运行审计数据量增长] -> 永久保留结构化摘要，详细原始响应按受控存储策略管理并脱敏。
- [隐藏被误解为删除] -> UI 明确说明只从默认列表隐藏，可通过筛选查看。
- [供应商取消是异步的] -> 保留 cancelling/最终状态语义，不提前宣称成功取消。

## Migration Plan

1. 先建立 run/step/attempt 状态和 fake provider 恢复测试。
2. 接入作品生成 DAG，再实现查询、取消和重试 API。
3. 原型确认后实现任务列表与右侧详情。
4. 回滚页面时保留所有任务和审计，停止新 attempt 领取但不删除上游身份。

## Open Questions

无阻塞问题；各 Seedance 模型是否支持取消由实施时能力目录决定。
