## Context

素材库以 `Material` 为聚合根，画布节点由前端列表派生，不持久化节点位置。现有实现把资产栏、画布和详情浮层同时常驻在一个工作区内，并在列表加载后自动选择首项；实际 AI 图片文件名较长，固定坐标与无高度限制的 Konva 文本导致节点内部错乱。

用户已确认 Pencil v2：默认状态隐藏详情，选择素材后打开右侧抽屉；素材卡片采用统一尺寸和稳定的标题、元信息区域。

## Goals / Non-Goals

**Goals:**

- 恢复画布为主视觉区域，详情按上下文出现。
- 保留新增、编辑、保存、归档和恢复完整闭环。
- 让不同长度文件名、不同素材数量和详情开关状态都不会造成节点重叠。
- 用自动化测试锁定状态行为和布局算法。

**Non-Goals:**

- 不修改素材 API、数据库或生命周期。
- 不新增画布位置持久化、拖拽编排或连线语义。
- 不实现移动端适配。
- 不扩展文件上传、语义检索或素材候选能力。

## DDD

详情抽屉不是新的领域对象，只是 `Material` 编辑能力的上下文界面。关闭详情仅清除前端选择/新建状态，不改变素材数据或生命周期。`active/archived` 仍由现有状态 API 维护。

## BDD

- 操作者进入有素材的素材库时，先看到资产栏和完整画布，不自动打开详情。
- 操作者点击资产项或画布节点时，该素材被选中并打开详情抽屉。
- 操作者关闭详情时，抽屉消失且画布重新使用释放的空间。
- 操作者点击新增素材时，新建抽屉打开并聚焦素材名称。
- 操作者切换素材类型时，只看到该类型适用的扩展字段。

## SDD

### 状态

`selectedMaterialId` 和 `creatingMaterial` 共同决定详情是否打开。列表刷新只校验当前选择是否仍存在，不再回退选择第一条素材。关闭动作同时设置 `selectedMaterialId=null`、`creatingMaterial=false` 并清理当前操作错误。

### 布局

Konva 节点使用纯函数计算位置。输入为素材列表、工作区宽度和详情打开状态；算法使用固定节点尺寸、水平/垂直间距、资产栏安全边距和详情抽屉安全边距计算列数，列数至少为一。标题使用固定宽高、两行换行和省略处理，元信息位于固定底部区域。

### 表单

通用字段始终显示：名称、类型、素材 URL、缩略图 URL、标签、来源备注、授权备注。扩展字段按类型显示：

- `video` / `audio`：时长、格式。
- `image`：宽度、高度、格式。
- `subtitle`：字幕语言、字幕格式。

提交 payload 继续沿用现有转换逻辑，不修改接口契约。

## TDD

- 页面测试先证明素材加载后详情默认不存在，选择后出现，关闭后消失。
- 页面测试覆盖新增入口打开抽屉并聚焦、切换类型后仅显示相关字段。
- 布局纯函数测试覆盖详情关闭/打开时列数变化、窄画布至少一列、所有节点坐标不越过安全区域。
- E2E 覆盖默认画布、详情打开/关闭和长文件名节点不发生可见重叠。

## Decisions

1. 采用同页右侧抽屉，而不是独立详情页或模态框。原因是素材选择与画布浏览需要保持上下文，且已确认原型采用该模式。
2. 使用可测试的确定性布局函数，而不是继续写死索引到坐标的映射。节点位置仍不持久化，但可随工作区宽度稳定重排。
3. 不引入新图标依赖。项目当前没有图标库，关闭按钮使用可访问文本符号并保持稳定尺寸，避免为单个控件扩大依赖面。

## Risks / Trade-offs

- [详情关闭后用户失去当前编辑上下文] -> 关闭只由明确按钮触发；未保存内容不在筛选或窗口变化时自动丢弃。
- [Konva 无 DOM 文本盒，E2E 难以直接读取节点内部布局] -> 纯函数单元测试验证坐标边界，E2E 通过 canvas 像素范围和面板几何验证整体布局。
- [小尺寸桌面可用画布不足] -> 列数下限为一，工作区自身保持裁切，节点从安全起点纵向排布。

## Migration Plan

无需数据迁移。发布前运行前端单元测试、lint、build 和素材库 E2E；回滚时只需回退前端文件，不影响已有素材数据。

## Open Questions

无。Pencil v2 已由用户明确确认开发。
