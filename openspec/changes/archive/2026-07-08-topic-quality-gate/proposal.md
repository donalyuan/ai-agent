# topic-quality-gate Proposal

## 背景

内容策略模块已经具备选题池、历史生成、补充批次、主题组评审和脚本产出优先级排名。当前用户反馈的核心问题不是选题数量不足，而是 `topic` Agent 生成质量不稳定：选题可能太泛、重复、偏离账号定位、难以脚本化，或出现评分虚高且理由不可信。

现有生成链路已使用严格 JSON Schema，能保证结构正确，但生成后只校验字段完整和分数范围；主题组评审发生在选题入库之后，只作为运营筛选辅助，无法阻止低质候选进入可用选题池。

## 目标

1. 在 `topic` Agent 生成链路中新增质量闸门，在候选入库前评估质量。
2. 质量闸门覆盖账号匹配度、具体度、差异化、脚本化可行性、风险与评分可信度。
3. 首轮低质比例过高时，最多自动重写一次，控制成本和等待时间。
4. 只把通过质量闸门的候选写入 `content_topics`，淘汰候选仅保存在质量报告中。
5. 历史生成页和当前选题池展示质量摘要、质量分和淘汰原因，降低人工筛选成本。

## 非目标

1. 不新增完整账号管理、账号策略编辑或账号切换能力。
2. 不改变 `ContentTopic.status` 生命周期，不新增 `quality_rejected` 业务状态。
3. 不让 AI 自动确认、归档、删除选题或生成脚本。
4. 不接入外部热点、竞品抓取、发布数据回流或长期学习模型。
5. 不覆盖移动端原型、移动端适配或移动端验收。

## 影响范围

- 数据库新增选题质量评估快照表。
- 后端新增质量闸门 domain model、repository、API、LLM 输出校验和 Agent run/step 记录。
- `topic` Agent 生成和补充生成链路调整为“生成候选 -> 质量评估 -> 必要时重写 -> 入库通过项”。
- `apps/video-agent` 内容策略页、历史生成页和 API client 展示质量结果。
- OpenSpec、项目记忆、后端测试、前端测试和 E2E 需要同步更新。
