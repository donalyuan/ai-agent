## Why

作品库已经能够把明确完成版本交接给发布运营，但当前没有消费交接单的发布页面、平台准备流程或发布结果记录。抖音和小红书个人账号又不具备可用的官方账号 OAuth 与自动发布能力，因此需要把真实可执行的人工发布过程建设成可计划、可追踪、可审计的运营闭环，而不是继续保留无法落地的账号管理和自动排程承诺。

## What Changes

- 新增“发布工作台”，消费现有 `publication_handoffs`，按选定作品版本创建唯一的发布计划。
- 为同一发布计划建立相互独立的抖音和小红书发布目标，支持平台文案、封面、计划发布时间、准备状态和人工发布结果。
- 生成绑定明确作品版本与平台文案快照的发布包，提供成片/封面下载、文案复制、官方创作者入口和完整性校验。
- 以 `draft -> ready -> handed_off -> published | needs_attention | cancelled` 管理人工发布目标；打开官方页面只表示已交接，不得自动标记发布成功。
- 发布成功必须由操作者登记官方作品链接和实际发布时间；允许修正误录结果，但保留追加式审计事件。
- 保留可选计划发布时间和逾期提醒，但不创建自动发布 Worker、不保存平台登录凭据，也不控制第三方创作者网页。
- 将计划中的“发布排程”入口调整为“发布工作台”，提供待发布与发布记录视图。
- 明确旧 `accounts`、`publish_tasks` 不再作为新发布域写模型；本 change 不删除历史表，也不建设抖音/小红书账号聚合。
- 发布文案 Agent、官方 API 自动发布、账号 OAuth、自动结果同步和数据指标回流不在本 change 内，分别由后续 change 定义。

## Capabilities

### New Capabilities

- `manual-publication-operations`: 定义人工发布计划、平台目标、发布包、计划提醒、官方网页交接、人工结果登记和审计要求。

### Modified Capabilities

- `video-workspace-navigation`: 将 Phase 5 的计划入口从“发布排程”调整为可用的“发布工作台”，并按数据库菜单配置路由到人工发布运营页面。

## Impact

- 数据库：新增发布计划、平台目标、发布包和追加式事件表；保留现有 `publication_handoffs` 作为不可变上游边界。
- 后端：新增发布计划查询、平台草稿、发布包、交接动作、结果登记与修正 API；所有写操作需要幂等保护和凭据脱敏约束。
- 前端：新增 `/publishing/workbench`，从作品库“进入发布”后跳转对应计划；提供待发布、发布记录、平台文案和人工检查清单。
- 存储：复用作品 artifact；发布包按 manifest hash 生成并校验，不重复转码成片。
- 迁移：数据库菜单替换未启用的 `publish-scheduler` 规划节点；旧发布表只保留历史兼容，不被新代码写入。
- 验证：新增领域、数据库、API、前端和桌面端 E2E，覆盖版本绑定、双平台隔离、发布包完整性、状态真实性和敏感信息禁入。
