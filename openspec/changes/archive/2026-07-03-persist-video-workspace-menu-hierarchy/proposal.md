## Why

当前 `apps/video-agent/app/page.tsx` 仍把左侧入口硬编码为 6 个 Agent：选题、脚本、素材、视频、发布、优化。这个结构只表达底层能力预留位，没有表达用户确认的视频生产业务流程：内容策略 -> 脚本创作 -> 素材管理 -> 作品生产 -> 发布运营 -> 数据分析 -> 工作流任务。

如果继续用前端常量控制菜单，后续无法按数据库配置菜单层级、排序、启用、隐藏、禁用和模块归属，也无法在 `admin/` 控制面逐步接入菜单控制。因此需要创建一个 OpenSpec change，把视频工作台菜单改为数据库持久化配置，并让前端按业务菜单树渲染，而不是按 Agent 数组渲染。

## What Changes

1. 新增视频工作台菜单持久化模型，支持父子层级、排序、可见性、启用状态、模块归属和 Agent 关联。
2. 新增后端只读菜单接口，供 `apps/video-agent` 获取树形菜单。
3. 初始化 7 个一级业务菜单：内容策略、脚本创作、素材管理、作品生产、发布运营、数据分析、工作流任务。
4. 将当前脚本生成、脚本列表和时间轴对照详情归入“脚本创作”菜单下，默认进入脚本创作。
5. 前端移除 6 个硬编码 Agent 一级入口，改为读取数据库菜单树；底层 Agent 状态只作为二级菜单、模块标记或状态信息展示。
6. 保留 `admin/` 作为未来菜单控制入口的归属边界，本 change 不把平台控制面能力放进 `apps/video-agent`。

## Non-goals

1. 不实现完整菜单管理后台 UI；后续如要编辑菜单，应在 `admin/` 或后端控制面中单独推进。
2. 不改变脚本生成、脚本详情和脚本状态更新 API 的业务语义。
3. 不把模型 Key、模型路由、MCP、Worker、队列、系统日志、权限审计或成本限额放进视频工作台。
4. 不新增移动端验收；当前视频工作台仍按桌面端运营生产场景验收。
