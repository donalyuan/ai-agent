## Context

仓库目前只有规则、OpenSpec 和 Markdown 项目记忆，没有可验证的产品、技术栈、数据模型或外部平台集成。现有根规则包含已失效的本地 skill 路径、强制 `Pencil MCP` 流程，以及与仓库事实不符的第三方平台、视频、migration 和 JSONB 约束。

本变更只整理项目规则与当前会话可用能力的路由，不记录宿主机安装细节，也不把能力可用性扩展为跨设备的仓库前提。

## Goals / Non-Goals

**Goals:**

- 使根规则保留已确认的沟通、记忆、事实优先、OpenSpec、验证和 Git 授权边界。
- 为 UI、浏览器交互/端到端检查及有明确边界的截图建立清晰的 skill 路由。
- 以简洁的当前交接记录此次规则调整和仍待确认的项目事实。

**Non-Goals:**

- 不安装、复制或配置 skill、MCP、浏览器依赖或其他工具。
- 不定义产品架构、前端设计系统、数据库结构、外部平台或费用策略。
- 不创建应用代码、测试、依赖或运行命令。

## Decisions

### 规则以仓库事实和会话能力分别表达

根规则把可验证的项目事实与当前会话中的 skill 路由分开：项目事实继续由代码、配置和记忆文档确定；当任务类型匹配且 skill 在会话中可用时，使用 `frontend-design`、`playwright`，或在明确边界内截图。这避免将某台宿主机的安装状态写成任何环境都必须满足的仓库事实。

备选方案是保留特定 `.claude/skills` 或 MCP 前置条件。该方案已无可用性证据，并会阻塞本可在当前能力内完成的任务，因此不采用。

### 前端截图采用任务限定的自动授权

执行当前项目前端开发、调试或验证任务时，当前项目的浏览器页面或应用窗口可以自动截图；浏览器页面优先使用 `playwright` 的工具内截图，代理自查用的截图仅保存于临时目录。整个桌面、其他应用、其他项目或无关内容即使发生在前端任务中也不属于自动授权范围；非前端任务中的任何截图同样必须事前向用户索要明确授权。

备选方案是对所有截图维持逐次用户授权。该方案会阻碍当前前端任务的必要自查，且用户已明确授予了更窄的任务级授权，因此不采用。另一备选方案是为前端任务自动允许任意屏幕截图；它会捕获范围外内容，不满足最小授权边界，因此不采用。

### 删除无证据的领域和数据约束

删除 Runway、可灵、抖音、小红书、视频费用、migration、JSONB 和 GitNexus 的专门规则。当前仓库不存在支撑这些约束的代码、配置、需求或产品事实；泛化的事实优先、授权、验证和外部副作用控制仍足以在未来出现相应证据时约束实现。

备选方案是保留这些限制以作预防。该方案会把未知项目需求伪装成既定事实，因此不采用。

### 用交接替换过期的当前状态

`HANDOFF.md` 只记录变更已完成、已验证的规则路由和仍待确认的范围，不复制完整规则或执行流水账。后续任务仍以当前代码与可执行配置为权威来源。

## Risks / Trade-offs

- [未来环境未提供某个 skill] → 规则仅在该 skill 对当前会话可用时才路由；不可用时保留原始限制并说明缺失条件，不静默冒充已执行。
- [前端截图越过任务边界] → 自动授权仅覆盖当前项目、当前前端任务所需的浏览器页面或应用窗口；其他内容与非前端任务均须事前明确授权，浏览器自查优先使用 `playwright` 工具内截图并存放临时目录。
- [删除领域专用限制被误解为允许未授权外部操作] → 保留通用授权、事实优先、验证和 Git 边界；新增外部能力前仍须由需求和仓库证据确定。
- [根规则与 Claude 专有表述重复或漂移] → `AGENTS.md` 保持项目通用入口，`CLAUDE.md` 只补充 Claude 使用时的等价执行细则，并在同一变更中核对二者。
