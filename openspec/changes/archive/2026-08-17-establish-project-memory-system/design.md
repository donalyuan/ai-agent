## Context

仓库当前仅有项目规则与 OpenSpec 初始化内容，旧规则引用的 `MEMORY.md` 和 `docs/memory/` 已不存在。当前树无法验证此前记录的产品定位、技术栈、运行命令或部署结构，因此持久记忆必须以可检查的仓库事实为边界。

## Goals / Non-Goals

**Goals:**

- 用版本控制的 Markdown 保存可复用的项目事实、决策、交接和已证实的排障信息。
- 为代理提供固定读取顺序、事实源优先级和任务后维护规则。
- 用 ADR 保留方案选择与取舍，避免将未经验证的历史内容作为事实传播。

**Non-Goals:**

- 不接入 Basic Memory MCP、向量库、数据库、知识图谱或常驻服务。
- 不创建产品源码、依赖清单、运行配置、`.gitignore` 规则或用户级配置。
- 不以文档替代当前代码、测试、schema 或可执行配置的事实地位。

## Decisions

1. 采用 `docs/agent/` 五文件分类：`PROJECT.md` 记录当前事实，`DECISIONS.md` 索引长期决策，`HANDOFF.md` 记录可继续执行的当前状态，`TROUBLESHOOTING.md` 只收录已证实问题，`README.md` 解释入口。它比单一大文件更便于按需读取和小范围维护。
2. 使用 `docs/adr/` 保存不可逆或长期有效的选择；本次以 ADR-0001 记录第一阶段方案。替代方案是仅维护会话记忆或引入检索服务，前者无法跨会话审计，后者超出当前证据与范围。
3. 在 `AGENTS.md` 固化读取顺序和事实源优先级。当前代码、测试、schema、可执行配置优先；ADR 与当前架构次之；`PROJECT.md` 与 `DECISIONS.md` 再次；`HANDOFF.md` 与 `TROUBLESHOOTING.md` 最后。该规则防止文档覆盖可运行事实。
4. 仅记录已确认、可复用的信息，并以相对链接关联文档；禁止保存秘密、凭据、令牌、私有数据及设备相关绝对路径。

## Risks / Trade-offs

- [Markdown 依赖人工维护，可能滞后] → 在 `AGENTS.md` 要求任务完成后更新受影响的事实、决策、交接或排障记录，并以当前实现为准。
- [初始化阶段信息有限] → 对产品、技术栈、命令、部署和外部服务统一标记为待确认，不从已删除结构推断。
- [文档膨胀或重复] → 保持文件精简，优先链接到权威来源，而非复制长篇内容。

## Migration Plan

1. 建立新的 `docs/agent/` 与 `docs/adr/` 入口及 ADR-0001。
2. 将项目规则从已删除路径迁移到新入口，并清理未经当前树验证的旧状态声明。
3. 通过 OpenSpec artifacts、链接检查、路径与秘密扫描、Git diff 检查验证。

回滚时可移除本次新增文档并恢复两个规则文件的先前版本；本次不迁移运行时数据，也不触发外部副作用。
