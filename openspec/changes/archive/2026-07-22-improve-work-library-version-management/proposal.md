## Why

作品生成当前把每次规划保存都当成新版本，导致未运行草稿持续递增；作品详情又把全部历史版本和原始技术快照同时铺开，操作者难以识别当前草稿、可用成片与失败审计。需要统一修正版本创建边界和详情信息层级，避免数据继续膨胀并恢复可扫描性。

## What Changes

- 将版本创建边界从“每次创建计划”改为“新的生产意图”：同一初始规划、编辑会话或整体重生成会话复用其未确认草稿。
- 草稿确认后锁定同一版本并创建运行；已确认或已运行版本继续保持不可变。
- 增加一次性历史治理，只删除无运行、无调用尝试、无产物、无发布引用、非当前版本且未被其他版本引用的冗余草稿；失败运行及其审计记录永久保留。
- 作品详情改为业务摘要优先，技术快照默认折叠，空时间轴使用紧凑状态。
- 版本记录按“当前草稿 / 可用成片 / 失败与早期记录”分组，历史记录默认折叠，并保持明确的版本选择与对比入口。
- 详情主体和版本栏保持固定高度；主业务区不产生独立滚动，展开后的失败与早期记录在限定区域内独立滚动，避免版本数量撑高或撑破详情卡片。
- 当前草稿的修改入口改为作品 Agent 对话；操作者用自然语言持续修改同一草稿，页面不再暴露原始 `prompt_snapshot` 编辑、手工保存和手工分析差异流程。
- 作品 Agent 将受约束的结构化补丁写入当前编辑草稿并生成待确认 diff；失败时保留用户消息，不自动调用视频、TTS、ASR 或发布能力。
- 作品详情业务工作区严格映射已确认的 v3 Pencil 原型，同时继续复用全站统一顶栏和左侧菜单骨架。

## Capabilities

### New Capabilities

- `work-library-version-governance`: 定义作品草稿复用、版本创建边界、安全历史治理、版本分组展示和详情渐进披露规则。

### Modified Capabilities

无。

## Impact

- 后端：`work_generation_repository` 的作品/版本创建事务、版本引用检查、数据库迁移及 `work` Agent Runtime。
- 前端：作品详情业务摘要、空时间轴、技术快照、版本分组、Agent 对话和 v3 工作区结构。
- 数据：现有失败版本保留；仅满足完整安全谓词的冗余未运行草稿可清理。
- 测试：Rust repository/database/routes、前端单测和作品库 E2E。
