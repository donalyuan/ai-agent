# 画面生成边界重定义 Design

## Context

既有 `script-to-asset-generation` 已实现脚本分镜图片候选，并保留“AI 视频任务先 draft、再二次确认”的旧设计。新产品流程要求所有 Seedance 视频在作品级汇总全部主画面和镜头描述后一次确认，因此旧视频入口必须停止新增，避免重复调用和审计分裂。

## Goals / Non-Goals

**Goals:**

- 画面生成成为作品生产前的图片准备边界。
- 每个分镜最多一个可用主图片，并向下游提供完整清单。
- 旧视频记录可查但不再产生新数据。

**Non-Goals:**

- 不重写已完成的图片 provider 和存储链路。
- 不迁移或删除历史视频任务。
- 不负责作品提示词、Seedance 分段或成片合成。

## DDD

`SceneAssetCandidate` 继续属于画面准备上下文，候选来源为旧素材或 AI 图片。它负责 `candidate/selected/rejected/failed` 状态和同分镜主图片唯一约束。

旧 `video_draft/video_generation` 退出新写入模型，只作为历史审计投影。新视频任务由作品生产的 `WorkGenerationRun` 和 `video_segment` 步骤承担，两个上下文不得双写。

画面生成向作品生成发布 `SceneVisualManifest`：脚本、分镜顺序、主素材 ID/稳定 URL、镜头描述、旁白及来源快照。Manifest 只是输入快照，不在画面生成中创建作品任务。

## BDD

操作者从素材管理进入“画面生成”，选择脚本后可以生成和预览图片候选、排除候选、单镜头重生，并为每个分镜选定一张主图片。页面不再展示 AI 视频草稿或确认按钮。

进入作品生成时，系统检查所有分镜。任何分镜缺少主图、主图已归档或候选失败，都明确标出并返回画面生成处理；全部有效才输出有序清单。

## SDD

菜单继续由 `video_workspace_menus` 驱动，使用稳定 module key，修改显示名称和描述，避免前端硬编码。现有素材生成路由可以保留兼容的图片路径，但不得再创建 `task_type=video` 或旧视频草稿。

历史视频 API 仅提供查询：返回旧任务状态、参数、错误和结果。不得提供确认、恢复、重试或继续执行动作。新作品生产不得写入旧表。

`SceneVisualManifest` 必须按稳定分镜序号排序，并包含脚本/分镜版本与素材快照，以便作品规划发现上游输入变化并使旧计划失效。

## TDD

- 菜单 migration/API 测试覆盖新名称、排序和数据库单一来源。
- Repository/API 测试覆盖主图片唯一性、完整清单、归档/失败素材阻断。
- 回归测试确认图片候选、预览、重生和自管素材不受影响。
- 负向测试确认任何新入口都无法创建旧 `video_draft/video_generation`。
- E2E 覆盖“缺图返回画面生成”和“完整主图进入作品生成”。

## Decisions

### 停止旧写入而不删除历史

历史记录具备审计价值，硬删除会破坏已发生调用事实；继续写入则造成两套视频领域模型。因此选择只读冻结。

### 以主画面清单连接作品生成

下游读取稳定 manifest，而不是自行拼接候选查询，便于一致校验输入完整性和计划过期。

## Risks / Trade-offs

- [旧书签仍指向视频草稿] -> 显示只读历史说明和作品生成新入口，不做隐式重跑。
- [菜单改名影响自动化] -> 以稳定 module key 路由，更新可见标签和 E2E 选择器。
- [主图在计划后变化] -> manifest 带版本摘要，作品确认时重新校验。

## Migration Plan

1. 先增加禁止新视频任务的后端测试与约束。
2. 修改菜单和页面，移除旧视频创建操作。
3. 保留历史只读查询，并让作品生成消费新 manifest。
4. 回滚只恢复菜单展示，不得恢复旧视频外部调用写路径，除非另行评审。
