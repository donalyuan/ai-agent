# 设计文档

## 总体方案

智能体工作台落在 `admin/`，用于验证 video-agent 的第一个可用业务闭环。工作台壳层必须面向六个 Agent 预留菜单和布局位置，本 change 只实现脚本 Agent 的可用模块。后端在现有 `projects` 表之上补齐最小项目 API；前端使用 Next.js App Router 构建单页工作台，通过 typed API client 调用 `novex-api`。

工作台首屏不做营销页，直接呈现操作界面：全局智能体菜单、项目选择、脚本列表、分镜详情、生成配置和状态操作。页面应偏向数据密集、可扫描、低装饰的运营工具，而不是卡片堆叠式宣传页面。

## 设计参考

### 选择的设计系统参考

1. `Ant Design`：借鉴后台工作台的信息密度、列表筛选、表单布局和状态反馈。
2. `IBM Carbon`：借鉴严谨的表单分组、错误提示、加载/空状态和可访问性约束。
3. `GitHub Primer`：借鉴简洁的状态标签、边框、列表行操作和低干扰配色。

### 借鉴模式

1. 左侧全局智能体菜单、脚本列表、中间详情、右侧操作面板的分栏工作台。
2. 状态 badge 使用语义色，避免大面积单色主题。
3. 表单控件密度适中，输入、select、segmented control、按钮和反馈位置稳定。
4. 空状态、错误状态和加载状态与工作流位置绑定。

### 避免模式

1. 不做 hero、大插画、渐变装饰背景或营销式首屏。
2. 不使用嵌套卡片；页面区域用布局分栏，卡片只用于脚本列表项或分镜条目。
3. 不使用单一紫蓝、深蓝、米色或橙棕主导调色。
4. 不用隐藏项目 ID 的硬编码入口替代项目选择。

### DESIGN.md

由于仓库当前没有项目根 `DESIGN.md`，实现前必须新增一个 `AI-AGENT` 工作台设计上下文，定义颜色、字体、间距、表单、按钮、状态标签、列表和响应式规则。`DESIGN.md` 不应复制某个外部系统，而应把上述参考转化为本项目自己的操作台设计规范。

## 范围划分

### 后端最小项目 API

现有后端只有 `ProjectRepository::project_exists`，不足以支撑前端选择项目。新增能力限制在工作台必要范围：

1. `GET /api/projects`：返回项目列表，默认按 `created_at DESC`。
2. `POST /api/projects`：创建项目，字段为 `name`、`positioning`、`description`。
3. 响应结构包含 `project_id`、`name`、`positioning`、`description`、`status`、`created_at`、`updated_at`。

不实现项目删除、归档、编辑、权限或多租户。

### 前端工作台

工作台包含五个核心区域：

1. 顶部栏：产品名 `AI-AGENT`、二级标题“智能体工作台”、当前 API 状态、项目选择入口。
2. 全局智能体菜单：预留选题智能体、脚本智能体、素材智能体、视频智能体、发布智能体、优化智能体六个入口；当前高亮脚本智能体。
3. 左侧脚本列表：状态筛选、脚本标题、分镜数、创建时间、状态标签。
4. 中间详情区：脚本标题、总时长、分镜时间轴，以及旁白/画面指令对照。
5. 右侧生成与操作区：选题输入、风格选择、分镜数选择、生成按钮、状态更新按钮。

本 change 仅覆盖桌面工作台。移动端布局和移动端原型暂不纳入本次范围，后续如需要应单独提出 OpenSpec change。

## 数据流

1. 页面加载时读取 `NEXT_PUBLIC_API_BASE_URL`，调用 `/health` 和 `/api/projects`。
2. 如果没有项目，提示先从顶部选择已有项目；脚本工作台不提供项目创建或项目管理入口。
3. 选中项目后调用 `/api/projects/:project_id/scripts` 加载脚本列表。
4. 点击脚本列表项后调用 `/api/scripts/:script_id` 读取详情。
5. 生成脚本时提交 `project_id`、`topic`、`style`、`scene_count`，其中 `scene_count` 支持 3 到 12；成功后将新脚本插入列表并打开详情。
6. 更新状态时调用 `/api/scripts/:script_id/status`，成功后同步详情和列表状态。

## 错误与状态处理

1. API 不可用：顶部显示服务不可用，禁用生成与状态更新，但保留页面结构。
2. 无项目：提示先从顶部选择已有项目，不显示项目创建或项目管理表单。
3. 无脚本：展示空列表状态，并保持生成面板可用。
4. 生成中：按钮进入 loading 状态，表单保持尺寸不变，禁止重复提交。
5. LLM 或后端错误：在生成面板内展示错误消息，不清空用户输入。
6. 状态更新失败：在详情区展示错误，保留原状态。

## 脚本展示方式决策

脚本详情采用“时间轴对照视图”，而不是单纯卡片流或纯表格。左侧时间轴用于表达分镜顺序和节奏节点，右侧对照区并排展示旁白与画面指令，便于操作者同时检查叙事推进和镜头执行信息。脚本列表仍保留在左侧，生成与状态操作仍保留在右侧。

## 测试策略

1. 后端采用现有 Rust 测试风格，先补项目 API 路由/仓储测试，再实现。
2. 前端新增轻量测试基础，覆盖 API client、状态归并逻辑和关键组件渲染。
3. 实现完成后运行 `cargo test -p novex-api`、`npm run lint`、`npm run build`、前端测试命令。
4. 通过本地服务手动验证桌面工作台完整闭环，确认无项目、创建项目、生成脚本、查看分镜、更新状态都可用。

## 原型门禁

实现前必须完成 `Pencil MCP` 原型，至少覆盖桌面工作台、生成中、错误、无项目和无脚本状态。用户确认原型后才能进入编码。
