# 脚本 Agent 工作台提案

## 背景

`script-agent-mvp` 后端已经提供脚本生成、读取、列表和状态更新 API，但当前 `admin/` 仍是环境健康占位页，操作者无法在浏览器内完成脚本 Agent 的核心闭环。

项目记忆已确认当前优先级是建设脚本 Agent 前端工作台，打通“生成脚本 -> 查看分镜 -> 更新状态”的可用流程。由于脚本生成接口要求有效 `project_id`，工作台需要项目选择能力，不能依赖硬编码项目 ID；项目创建和管理不属于当前脚本工作台范围。

## 目标

1. 在 `admin/` 中提供脚本 Agent 工作台作为首屏业务体验。
2. 支持选择已有内容项目，并基于项目加载脚本列表。
3. 支持提交选题、风格和 3-12 分镜数，调用后端生成结构化脚本。
4. 支持查看脚本标题、hook 和有序分镜明细。
5. 支持将脚本状态更新为 `draft`、`approved` 或 `archived`。
6. 在实现前完成设计上下文和 `Pencil MCP` 原型确认。
7. 本 change 仅覆盖桌面工作台；移动端布局暂不纳入本次范围。

## 非目标

1. 不做可视化脚本编辑器或逐字段保存。
2. 不做多人协作、评论、审批流或版本 diff。
3. 不做素材匹配、视频生成、发布任务编排。
4. 不引入完整账号权限/RBAC 控制面。
5. 不把脚本 Agent 工作台拆到独立 `apps/video-agent` 前台；本阶段先在 `admin/` 验证闭环。
6. 不做移动端工作台适配或移动端原型。

## 成功指标

1. 操作者可以选择已有项目并生成第一条脚本。
2. 生成成功后，页面展示标题、hook、分镜旁白、视觉描述、情绪和时长。
3. 脚本列表能按当前项目和状态筛选，并能打开已有脚本详情。
4. 状态更新后，列表和详情中的状态保持一致。
5. 无项目、无脚本、生成中、生成失败、接口不可用都有明确界面状态。
6. `cargo test -p novex-api`、`npm run lint`、`npm run build` 和新增前端测试通过。

## 设计前置约束

本 change 涉及前端页面新增/修改，必须遵守 `docs/memory/frontend-design-skill-requirement.md`：

1. 先使用 `.claude/skills/awesome-design-md` 补齐项目根 `DESIGN.md`。
2. 先使用 `.claude/skills/awesome-design-systems` 选择真实设计系统参考。
3. 进入实现前必须完成 `Pencil MCP` 原型确认。

若当前环境没有暴露 `Pencil MCP` 工具，必须暂停实现并由用户决定是启用 Pencil，还是明确批准使用替代静态原型。
