# 作品库管理 Design

## Context

作品是面向运营者的内容实体，版本则是一次确定的生产快照。局部修改、整体重生成和发布交接都必须指向明确版本，否则“最新作品”会随草稿变化而污染下载、审计和发布。

## Goals / Non-Goals

**Goals:**

- 以作品聚合多个不可变版本，并提供网格/列表管理。
- 从历史版本派生草稿，先做差异与影响分析，再执行局部重生成。
- 下载和发布交接始终绑定明确完成版本。

**Non-Goals:**

- 不负责运行 DAG、provider 重试和 FFmpeg 执行。
- 不管理发布任务状态。
- 不对 Seedance 不可分轨原声伪造可下载分轨。

## DDD

`Work` 是作品聚合根，保存账号/项目归属、名称、封面、当前展示版本和 `active/archived` 状态。`WorkVersion` 是不可变快照，状态为 `draft -> confirmed -> running -> completed | failed`；进入 confirmed 后不能原地修改。

`WorkArtifact` 绑定具体版本，角色包括成片、字幕、混音、可用分轨、制作包和中间可复用结果。`WorkTimeline` 保存该版本的视频、TTS/原声、已有音频和字幕引用。

`WorkVersionDiff`/影响分析比较来源版本和新草稿，把字段变化映射到受影响节点。全局比例/分辨率变化影响全部视频分段；字幕文本/样式/烧录开关只影响字幕和最终合成。

## BDD

操作者进入作品库默认看到缩略图网格，可切换列表且筛选状态不丢失。详情可选择任意版本预览对应成片和时间轴，不能用最新草稿替代所选版本。

从完成版本“继续修改”时创建新草稿。Agent 修改后先展示差异、受影响任务、再次调用资源用量以及复用素材；用户确认后才交给作品生成运行。

空白且从未调用外部服务的作品可以删除。只要已有运行或产物，就只能归档。下载和进入发布都必须显式选择完成版本。

## SDD

### 版本不可变

版本确认时保存来源版本、计划、主图片、模型/能力、音色、提示词、输出、声音模式、字幕、时间轴和 artifact 引用快照。数据库和 API 均拒绝修改非 draft 版本；运行中 Agent 消息创建或更新后续 draft。

### 影响分析

差异输出至少包含路径、旧值摘要、新值摘要、影响节点、是否需要外部模型、任务数和非金额资源用量。规则必须确定性执行，Agent 可解释但不能绕过。确认使用 diff/plan 版本防止过期提交。

### 生命周期

硬删除条件同时要求：作品仅有空白 draft、无 generation run、无 provider attempt、无 artifact、无发布交接。其他作品只更新归档状态。归档不删除版本、素材、文件和审计。

### 下载与发布交接

下载必须按版本 artifact 清单和完整性校验返回。制作包包含版本、时间轴、提示词、参数和文件清单，不包含密钥。发布交接创建发布域草稿，保存 work/version/artifact 引用，不自动调用平台。

## TDD

- 版本：确认后不可变、运行中修改派生、整体重生成新版本。
- 影响分析：单镜头、全局分辨率、字幕、声音参数和未变化素材复用。
- 生命周期：空白删除、有 run/attempt/artifact/发布交接时拒绝、归档恢复。
- 下载：明确版本、完整性失败、不可分轨原声不伪造。
- 发布：选定完成版本交接、未完成阻断、发布状态不回写。
- 前端/E2E：网格/列表、详情、时间轴、版本对比和无金额字段。

## Decisions

### 作品身份与版本分离

作品提供稳定集合和归档入口，版本提供不可变生产事实。这样下载、发布和审计不会随最新草稿漂移。

### 影响分析确定性优先

影响规则由结构化字段和 DAG 依赖决定，Agent 只解释结果；避免 LLM 漏掉应重生节点或错误扩大范围。

### 有调用事实只归档

外部调用和版本产物必须永久可追溯，硬删除会破坏任务与素材引用，因此仅空白未调用草稿允许删除。

## Risks / Trade-offs

- [版本和素材数量增长] -> 默认只展示当前版本/活动作品，保留归档筛选和明确清理策略，不覆盖历史。
- [影响规则漏项] -> 以字段到 DAG 节点映射测试覆盖，全局参数采用保守全片影响。
- [制作包泄露凭据] -> 只包含脱敏快照和文件清单，显式测试密钥不存在。
- [发布错误版本] -> 发布交接必须携带显式 version ID，不自动选择最新。

## Migration Plan

1. 建立 Work/Version/Artifact 和不可变约束。
2. 接入作品生成结果和任务审计，再实现查询与版本派生。
3. 原型确认后实现网格/列表和详情。
4. 最后接入下载与发布草稿交接。
5. 回滚时停用菜单和写操作，保留所有作品与版本事实。

## Open Questions

无阻塞问题。发布运营具体字段由后续发布 change 定义，本 change 只规定交接契约。
