# account-strategy-profile Proposal

## 背景

内容策略模块已经具备选题池、历史生成、补充批次、主题组评审、脚本产出优先级排名和质量闸门。当前选题生成、质量闸门和主题组评审的上下文主要来自 `projects.positioning` 与 `projects.description`，信息过粗，无法稳定表达账号受众、内容支柱、风格禁区和选题偏好。

用户已确认第一版只做内容账号/策略资料沉淀，不做抖音、小红书等平台账号凭据或发布账号管理。现有 `projects` 仍作为内容生产边界和 `project_id` 外键来源，但 `apps/video-agent` 前端展示语义应逐步统一为“账号”。

## 目标

1. 为当前内容账号沉淀结构化策略资料，使选题 Agent 有稳定输入。
2. 在内容策略下新增独立二级页面“账号策略”，提供策略资料查看、AI 草稿生成和编辑保存。
3. 支持 AI 基于账号名称、定位摘要、描述和用户补充方向生成策略资料草稿。
4. AI 生成结果只作为草稿预填，必须经人工确认保存后才写入账号策略资料。
5. 让 `topic` Agent 生成、质量闸门和主题组评审统一读取最新账号策略资料。
6. 保持现有 `project_id` 链路兼容，不迁移脚本、选题、素材、任务等外键。
7. 明确区分内容账号资料与未来平台发布账号凭据。
8. 当前选题池不展示账号策略区块、策略资料状态/摘要或编辑入口。

## 非目标

1. 不接入平台账号凭据、Cookie、Token、发布授权或密钥管理。
2. 不实现抖音、小红书、B站、YouTube 等发布账号管理。
3. 不迁移现有 `projects` 外键，也不新增替代 `project_id` 的全链路主键。
4. 不自动抓取竞品账号、热点数据或外部平台画像。
5. 不改变 `ContentTopic.status` 生命周期，不让 AI 自动确认、归档、删除选题或生成脚本。
6. 不覆盖移动端原型、移动端适配或移动端验收。
7. 不在本版建设完整账号管理中心；后续账号独立出来时，再复用或迁移本版策略资料能力。

## 影响范围

- 数据库：扩展 `projects`，新增结构化账号策略 JSONB。
- 后端：扩展 Project domain model、DTO、repository 和更新接口。
- 后端：新增账号策略资料 AI 草稿生成接口，只返回草稿，不直接持久化。
- Agent Runtime：统一组装账号策略上下文，并注入选题生成、质量闸门、主题组评审 prompt。
- 前端：内容策略下新增“账号策略”二级页面，展示账号策略资料、编辑表单和 AI 草稿预填；顶部“当前项目”展示语义改为“当前账号”。
- 前端：当前选题池不展示账号策略区块、策略资料状态/摘要或编辑入口；账号策略资料只在“账号策略”二级页面维护。
- 原型：更新 `docs/prototypes/video-agent/video-agent.pen`，覆盖“账号策略”独立二级页、账号策略资料查看、AI 草稿生成和编辑保存。
- 测试：覆盖策略资料保存/读取、跨项目隔离、prompt 注入、前端编辑与错误态。
